## Next.js requires a planned major upgrade

Next.js 14 is outside the project's supported release lines. The official support policy lists 16.x as Active LTS and 15.x as Maintenance LTS; security releases for 15.x are scheduled through 2027-01-31.

The November 3, 2026 security release identifies Next.js 16.4.5 as the patched Active LTS release and 15.5.29 as the patched Maintenance LTS release. The official Next.js repository subsequently published 16.4.6 on November 9, 2026 as a backport bug-fix release. For a new upgrade evaluation, use the latest 16.4.x patch (currently 16.4.6), not 16.4.5 or an unsupported 14.x release.

References:
- https://nextjs.org/support-policy
- https://nextjs.org/blog/november-2026-security-release
- https://github.com/vercel/next.js/releases/tag/v16.4.6

## Safe upgrade sequence

Do not change only `package.json`: the lockfile must be regenerated by npm and validated with `npm ci`.

1. Evaluate Next.js 16.4.6 on an isolated upgrade branch, keeping `promptforge-v2-development` as the stable baseline.
2. Update React and React DOM together to the compatible React 19 release required by Next.js 16, and update matching React type packages.
3. Check compatibility of Supabase, Vitest, Testing Library, and all Next.js configuration and route-handler APIs.
4. Regenerate `package-lock.json` with npm; do not hand-edit lockfile versions.
5. Run `npm ci`, all Vitest tests, TypeScript, and the production build.
6. Add targeted regression checks for authentication/session handling, streaming AI responses, file uploads, route handlers, and Supabase SSR.
7. Review the full npm audit report and resolve critical/high advisories without applying broad force upgrades.
8. Only after all checks pass, propose the upgrade for review. Do not deploy automatically.
